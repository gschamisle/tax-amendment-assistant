# 세제개편안 상세본 — 문서 구조 분석

> 대상: `docs/세법개정 세트/2. 2026년 세제개편안 상세본.pdf` (재정경제부, 2026-08-03)
> 파싱: `kordoc` → Markdown (본문 171KB / 4,073줄)
> 작성 목적: 이 문서를 기계로 읽어 **개정 항목 ↔ 조문 매핑**을 뽑아 쓰기 위한 사전 분석

---

## 1. 왜 이 문서가 중요한가

**개정안이 어느 조문을 건드리는지, 입안자가 직접 밝혀 둔 정답지다.**

세부항목 제목에 근거 조문이 박혀 있다.

```
- ① 국내생산세액공제 요건 및 적용기한(조특법 §29①)
- ④ 수도권과밀억제권역 생산분에 대한 국내생산세액공제 적용배제(조특법 §130③)
- (2) 친환경 업무용 승용차 감가상각비 한도 조정(소득법 §33의2, 법인법 §27의2)
```

법률안(`일부개정법률안`)은 **무엇이 바뀌었는지**를 조문 순서로 적고, 상세본은
**왜·어느 조문을** 바꾸는지를 정책 항목 순서로 적는다. 둘을 대조하면
`scan_renumber_omissions`·`scan_parallel_omissions`가 못 잡는 종류의 어긋남
(예: 상세본에는 있는데 법률안에 반영이 없는 조문)이 드러난다.

부수 효과로 **약칭 체계가 확인됐다.** 문서 말미 `[참고] 법령명에 대한 약어 설명`이
`core/law_abbrev.py`의 표와 완전히 일치한다 — 국기·국징·조특·소득·법인·상증·종부·
부가·국조·농특·관세 × 법/령/칙. `§` 표기(`§29의2`, `§29③·④·⑤`)도 동일하다.
우리 도표 표기가 부처 공식 관례와 같다는 뜻이다.

## 2. 계층 구조

```
Ⅰ. 잠재성장률 반등 지원                 ← 대분류 (Ⅰ~Ⅴ)
  1. 미래성장동력 확충                   ← 중분류
    (1) 국내생산세액공제 신설            ← 항목 (362개)
      ① … 요건 및 적용기한(조특법 §29①)  ← 세부항목 (183개, 근거 조문 포함)
        |현행|개정안|                    ← 신·구 병렬표
        <개정이유> …
        <적용시기> …
```

`Ⅲ. 공정과세` 이하에는 `【소득세 및 법인세】`, `【양도소득세 및 상속·증여세】`,
`【부가가치세 등】`, `【관세】`, `【국세 제반 분야】` 같은 **세목 묶음**이 한 겹 더 들어간다.

| 구성요소 | 개수 |
|---|---:|
| 항목 `(1)` | 362 |
| 세부항목 `①` | 183 |
| 근거 조문 표기 `(법령 §조)` | 283 |
| `<개정이유>` | 284 |
| `<적용시기>` | 196 |

`<적용시기>`가 `<개정이유>`보다 88개 적다 — 시행일이 자명하거나 상위 항목에
한 번만 적은 경우가 있다. **항목마다 반드시 있다고 전제하면 안 된다.**

## 3. 병렬표 — 좌: 현행 / 우: 개정안

### 3.1 두 가지 렌더링

| 형식 | 개수 | 언제 |
|---|---:|---|
| GFM 파이프표 `\|현행\|개정안\|` | 250 | 셀 병합이 없는 단순 2열 |
| HTML `<table>` | 29 | 병합셀·중첩표(계수표 등)가 있을 때 |

kordoc은 병합·중첩표를 GFM으로 표현할 수 없어 `<table colspan/rowspan>`으로 내려준다.
**두 형식을 모두 처리해야 한다.** 특히 HTML 쪽은 표 안에 표가 들어가는 경우
(지방우대계수 표 등) 셀 경계가 뒤섞여 좌우 대응이 깨지므로, 기계 추출 시
**HTML 표는 신뢰도 낮음으로 표시하고 사람이 확인**하는 편이 안전하다.

### 3.2 셀 유형

좌측(현행) 189/319가 조문 요약, 65가 `<신 설>`, 65가 기타(표·계산식 등).

| 좌측 | 뜻 |
|---|---|
| `□ …` / `ㅇ …` | 현행 조문의 **요약** — 전문이 아니다 |
| `<신 설>` | 현행에 없음 (신설 조문) |

| 우측 | 개수 | 뜻 |
|---|---:|---|
| 개정 내용 | 210 | 실제 바뀌는 내용 |
| `(좌 동)` | 172 | 그 부분은 그대로 — **변경 없음** |
| `<삭 제>` | 2 | 삭제 |

`(좌 동)`이 172개나 되는 것이 이 표의 성격을 말해 준다. **바뀌는 부분만 보여주려고
만든 표**라서, 좌우 셀은 조문 전문이 아니라 발췌·요약이다.

## 4. 기계 판독의 한계 — 반드시 감안할 것

### 4.1 사람이 쓴 문서다 (사용자 확인 사항)

직원이 작성하고 과장·국장·실장 보고를 거치며 **검토자 스타일이 반영된다.**
같은 원칙으로 일관되게 쓰이지 않았다. 따라서:

- 항목 제목의 조문 표기 형식이 흔들린다 — `(조특법 §29①)` / `(조특법 §132·§144)` /
  `(소득법 §33의2, 법인법 §27의2)` / `(조특법·령)`처럼 조 번호 없이 법령만 적기도 한다.
- 근거 조문 표기가 283개인데 세부항목은 183개, 항목은 362개다. **모든 항목에
  조문이 달려 있지 않다.**
- 요약 문장의 기호 체계(`□` `ㅇ` `-` `➊` `*` `※`)가 계층을 뜻하지만 깊이가 일정하지 않다.

### 4.2 표는 조문 전문이 아니다

좌측 `현행`은 **요약**이다. 조문 원문과 문자 단위로 대조할 수 없다.
원문이 필요하면 `data/law-snapshots/`의 스냅샷을 봐야 한다.

### 4.3 PDF 조판 잔재

- 목차가 표로 잘못 인식돼 `<table>` 안에 점선 목차가 통째로 들어간다
  (본문 시작 `Ⅰ. 잠재성장률` 이전은 버리는 게 안전).
- 페이지 머리말·쪽번호(`- xii -`)가 본문에 섞인다.
- 어절 중간에서 줄이 끊긴다 — `core/pdf_bill_text.unwrap()`과 같은 복원이 필요하다.

## 5. 활용 방안

### 5.1 지금 바로 쓸 수 있는 것

**개정 항목 ↔ 조문 매핑 추출.** 세부항목 제목의 `(법령 §조)`를 파싱하면
"이번 개편안이 손대려는 조문" 목록이 나온다. 283건이 명시돼 있다.

이것을 법률안 파싱 결과(`manual_amendment_targets`)와 대조하면:

| 대조 결과 | 뜻 |
|---|---|
| 상세본에 있고 법률안에도 있음 | 정상 |
| 상세본에 있는데 법률안에 없음 | **반영 누락 후보** — 정책은 정해졌는데 조문이 안 만들어짐 |
| 법률안에 있는데 상세본에 없음 | 기술적 정비(번호 밀림·인용 정비)이거나 상세본 누락 |

세 번째 줄은 `scan_renumber_omissions`가 잡는 것과 겹치므로, 겹치지 않는 나머지가
검토 대상이다.

### 5.2 부수 정보

- `<적용시기>` → 부칙 시행일 검토 자료
- `<개정이유>` → 병행개정 판단 시 "이번 개정 내용이 대응 조문에도 해당하는가"의 근거
- `(좌 동)` 위치 → 조문 중 **바뀌지 않는 부분**의 명시적 표시

### 5.3 하지 말아야 할 것

- 좌측 셀을 현행 조문으로 신뢰하고 문자 대조하기 (요약이다)
- 모든 항목에 조문·적용시기가 있다고 전제하기
- HTML 표의 좌우 대응을 기계 판정만으로 확정하기
